# Moonlit Market video walkthrough

This walkthrough follows a small game from its first idea through AI-assisted rules and artwork, a table-driven deck, playtesting, checkpoints, and printable exports. The final video is written to `artifacts/demos/moonlit-market/turnbased-game-creation.mp4`.

The writing and artwork scenes use real AI requests through the local development account. They are not mocked responses. The CSV is a prepared design fixture; it was not generated by AI during the recording. The playtest opponent and balance experiments use the local strategy engine.

## Completed recording — September 8, 2026

The final edit is **5 minutes 32.68 seconds**, with captions and no audio, at
1600 × 1000 / 25 fps (H.264 MP4, about 18 MB). It follows the actual browser
workflow at normal speed, omitting recorder-operation gaps and unsuccessful
takes. `recording-original.json` preserves the unedited scene manifest.

Moonlit Market contains six designs and eighteen cards, a customized two-face
template with embedded AI artwork, five authored rules chapters plus the
structured component list, and five checkpoints. The video creates a
“Pricier market” branch, changes a cost, and restores the playtest baseline;
the discarded edit remains in a safety checkpoint.

The real dev-account rules and image requests both returned HTTP 200. Twenty
seeded balanced-versus-balanced games on the project's numeric cost/points
cards produced a 50% challenger win rate and a 70% starting-seat win rate.
The journal records that result as a question for human playtesting. The
external-agent scene exports a packet and validates one operator-supplied
AI decision from public state; it does not connect an automatic LLM runner.

Exports include six A4 duplex card pages (18 fronts and 18 backs), the
rulebook, reusable template JSON, agent packet, and a portable game archive.
The cards and rulebook also have PDFs saved from their exported HTML in
Chrome. For printing, use actual size and flip cards on the long edge.

The recording exposed two fixes included with the demo: numeric fields now
forward their accessible labels, and checkpoints save locally before a
bounded five-second remote-sync attempt. Remote syncing was unavailable
during the recording; local save, branching, and restore completed normally.

- [Card table](moonlit-market-cards.csv): six designs, eighteen copies, numeric costs, and a custom `points` field for prestige.

## Start an isolated recording

Run these commands from the repository root. Start the local development environment with `npm run dev` first. Real generation requires the local AI provider configuration and a development account with sufficient wallet balance.

The recorder needs an installed Playwright module and Chrome. It defaults to `/usr/bin/google-chrome` and `http://127.0.0.1:3000`. Set `PLAYWRIGHT_MODULE_PATH` to an installed Playwright package if automatic discovery cannot find one; `DEMO_CHROME_PATH` and `CODEX_BROWSER_URL` override Chrome and the app origin.

```sh
node scripts/demo/record-session.mjs
```

This starts a fresh, headless Chrome browser with a 1600 × 900 viewport. It does not attach to the usual browser profile or edit its existing projects. Sign in through the app's **Use local dev account** action for the real AI scenes. The recording context has its own browser storage and is closed when recording stops, so export the finished game before stopping.

The default output directory is `artifacts/demos/moonlit-market`. Use `DEMO_OUTPUT_DIR` for another recording directory when preserving an earlier take:

```sh
DEMO_OUTPUT_DIR=artifacts/demos/moonlit-market-next-take node scripts/demo/record-session.mjs
```

## Drive the recorder with JSON on stdin

Keep the recorder process open and send one JSON object per line. It reports readiness, command results, downloads, and errors on the terminal. This is an interactive operator tool; it does not run the entire walkthrough automatically.

Use `begin` and `end` to mark the portions that should appear in the edit. Actions performed between scenes stay in the raw recording but are omitted from the rendered video.

```jsonl
{"action":"goto","url":"#/new"}
{"action":"begin","title":"An idea becomes a game","caption":"Start Moonlit Market: two woodland traders, one tiny prototype."}
{"action":"fill","label":"Game name","value":"Moonlit Market"}
{"action":"fill","label":"Theme or first idea","value":"Woodland traders gather coins and race for prestige at a lantern-lit night market."}
{"action":"fill","label":"Players","value":"2"}
{"action":"click","name":"Create game"}
{"action":"saved"}
{"action":"pause","ms":1500}
{"action":"end"}
{"action":"snapshot"}
```

Locator commands accept `label`, `text`, `css`, or a role and accessible `name`; role defaults to `button`. Matching is exact. An optional `nth` selects a zero-based match. Available operator actions include:

| Action | Purpose |
| --- | --- |
| `goto` | Navigate to an app hash route or full URL. |
| `click`, `fill`, `select` | Operate the visible controls; `fill` accepts `delay: 0` for immediate text entry. |
| `begin`, `end` | Mark a scene with its title and caption. Beginning another scene closes the current one. |
| `pause`, `saved` | Hold a frame or wait for the app's local-save status. |
| `snapshot`, `screenshot` | Inspect page text or save a PNG; `screenshot` accepts a filename stem in `name`. |
| `run` | Execute local operator-authored async Playwright code for uploads, scoped controls, or assertions. |
| `stop` | Finish the scene, save downloads and the manifest, then close the recording browser. |

For example, after opening **Components → Data & copies → Import**, upload the prepared fixture through its real file input:

```jsonl
{"action":"run","code":"await page.getByLabel('Choose CSV or TSV').setInputFiles('docs/demos/moonlit-market-cards.csv');"}
{"action":"run","code":"await page.getByRole('dialog').getByRole('combobox').selectOption('replace');"}
{"action":"click","name":"Replace table"}
```

The import preview should show **6 designs · 18 cards**. The replacement controls appear when the component already has starter rows. Use the dialog-scoped combobox above because the wrapping **Import mode** label also includes its option text. Refer to the storyboard for the subsequent template, playtest, checkpoint, and export steps. Finish with `{"action":"stop"}`; stdin EOF also stops the recorder.

## Render the captioned video

The renderer requires Python 3, FFmpeg with `libx264` and the `ass` subtitle filter, and FFprobe. Its defaults are the executables `ffmpeg` and `ffprobe` on `PATH`.

```sh
python3 scripts/demo/render-walkthrough.py
```

An explicit manifest and output directory are also supported:

```sh
python3 scripts/demo/render-walkthrough.py artifacts/demos/moonlit-market/recording.json --output-dir artifacts/demos/moonlit-market
```

Use `DEMO_FFMPEG` and `DEMO_FFPROBE` when the binaries have different locations. Each variable also accepts a shell-style executable/wrapper command with arguments; the renderer parses it into an argument list.

```sh
DEMO_FFMPEG=/usr/bin/ffmpeg DEMO_FFPROBE=/usr/bin/ffprobe python3 scripts/demo/render-walkthrough.py
```

`recording.json` contains the raw video path and the scene boundaries. Review those boundaries and captions before rendering. A scene may include a positive `speed` value; values above one visibly add an “Accelerated” label to its caption. The renderer validates the scene times against the source recording.

The output is an H.264 MP4 at 1600 × 1000 and 25 fps. Titles and captions occupy an added band below the browser viewport. There is no spoken narration or audio track. The renderer also writes chapter files, a poster, and a render log. Final duration and observed walkthrough results belong to the completed recording rather than this recipe.

Verify the resulting video with an isolated Chrome playback check:

```sh
node scripts/demo/check-video.mjs artifacts/demos/moonlit-market/turnbased-game-creation.mp4
```

This checks metadata, playback, seeks and decoded frames near the beginning,
middle and end. Screenshots and `playback.json` go into the adjacent
`video-qa/` directory.

## Generated artifacts and the portable game

Generated recordings, downloads, and game data are ignored by Git under `artifacts/demos/`. The source scripts, storyboard, and CSV remain in the repository. With the default output directory, the recorder and renderer use these paths:

| Path below `artifacts/demos/moonlit-market/` | Contents |
| --- | --- |
| `turnbased-game-creation.mp4` | Final captioned walkthrough. |
| `poster.jpg` | Still image from the rendered video. |
| `raw/*.webm` | Original browser recording. |
| `recording.json` | Raw video path, scene timings, browser errors, and observed AI endpoint response statuses. |
| `timeline.json`, `commands.jsonl` | Recording progress and successful operator commands. |
| `captions.ass`, `chapters.vtt`, `chapters.md` | Caption styling and chapter metadata. |
| `render.log`, `render-work/` | Encoder output and intermediate scene clips. |
| `downloads/` | Files exported through the actual app, including artwork, printable HTML, agent packets, and the full game backup when those actions are performed. |
| `*.png` | Operator screenshots and the final recording frame. |

In **print & share**, **Download full backup** saves `downloads/moonlit-market-with-history.json` for the unrenamed game. This portable export carries the project and its version history out of the isolated recording context.

To continue designing in the usual browser, open a game there, go to **print & share**, and choose **Import a backup as a new game**. Select that exported JSON file using **Import game backup**. Importing creates a new game and leaves the currently open game intact.

The finished backup was verified through the actual import UI in a separately launched Chrome context. It created a new ID and the expected **Moonlit Market (imported)** name. All six designs, eighteen copies, embedded artwork, front/back layers, restored first-card cost of 1, five checkpoints, twenty-game experiment, finding, saved session, and active agent observation survived import and reload. The printable HTML contains eighteen fronts and eighteen backs on six A4 sheets; the card PDF has six A4 pages, and both rulebook formats show ages 8+ and 10–15 minutes. Verification made no AI requests and recorded no browser errors. Results, logs, and inspected screenshots are under `artifacts/demos/moonlit-market/verification/`, including `portable-import-verification.json`.
